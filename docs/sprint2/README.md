# Спринт 2 «Аудит вимог і стратегія тестування»

**Продукт:** П1 «ШопЛайн» (`shopline`)  
**Спринт:** 2 «Аудит вимог і стратегія тестування»  
**Дата оновлення:** 12.10.2026  
**Автори:** Бойко Євгеній, Кочаров Давид, Белінська Єлизавета, Матвієнко Владислав, Бобров Павло

## 1. Мета спринта

Перевірити якість специфікації вимог SRS «ШопЛайн» 1.0 до початку тестування за шістьма критеріями (однозначність, повнота, несуперечливість, простежуваність, здійсненність, тестопридатність) і запропонувати стратегію тестування продукту: рівні, типи, пріоритети.

Інкремент спринта: **Досьє якості v2** — реєстр дефектів вимог, виправлена SRS 1.1 і план тестування.

## 4. Результати аудиту

Вихідна SRS «ШопЛайн» 1.0 перевірена за таблицею розподілу розділів: кожен розділ незалежно переглядали двоє учасників, після чого аркуші зведено в єдиний реєстр, а спірні кандидати розглянуто окремо.

| Критерій | Дефектів у реєстрі |
|---|---|
| Однозначність | 4 |
| Повнота | 4 |
| Несуперечливість | 7 |
| Простежуваність | 4 |
| Здійсненність | 4 |
| Тестопридатність | 4 |
| **Разом** | **27** |

Серед чотирьох спірних кандидатів три прийнято (Д1–Д3, № 25–27), Д4 відхилено після обговорення. Норматив для команди з 5 осіб (не менше 20 дефектів, не менше 2 на кожен критерій) виконано.

Формулювання з позначкою «потребує підтвердження замовником» є пропозиціями команди. Питання до замовника зведено в розділі «Питання замовнику» у `SRS-1.1.md` (після журналу змін).

## 5. Як користуватися артефактами

1. Для перегляду змін у вимогах відкрийте журнал змін на початку [`SRS-1.1.md`](SRS-1.1.md): кожна правка містить ID вимоги, текст «було / стало», № дефекту і автора знахідки.
2. Для пошуку дефекту за ID або критерієм використовуйте аркуш «Реєстр» у `requirements-defects.xlsx` (колонки «Критерій», «Статус дефекту», «Розділ SRS»).
3. ID вимог не перенумеровуються: вилучений BL-30 зарезервовано, GUI-65 присвоєно другій вимозі GUI-60, U-30 — вимозі, яка не мала ID.
