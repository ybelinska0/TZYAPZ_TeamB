## 4. Нові дефекти за моїм `PromoCodeValidatorRulesTest` (чернетки)

Наступні вільні ID — BUG-019 і BUG-020. **Узгодьте з Матвієнком**, щоб він не завів ті самі дефекти під іншими номерами. Reviewer залиште порожнім: рецензує не автор.

### BUG-019: PromoCodeValidator відхиляє промокод у день закінчення дії (BL-70)

Мітки: `severity:normal`, `priority:P3`, `status:new`, `sprint:4`, `module`

**Severity:** Normal   **Priority:** P3   **Status:** New  
**Linked:** test `PromoCodeValidatorRulesTest.expiryDateIsInclusive` [daysAfterExpiry=0]; requirement BL-70

### Description
BL-70 вимагає, щоб дата закінчення дії була «не раніша за today (день закінчення включно)». Метод `validate` у день закінчення повертає непридатний код із причиною про минулий строк, а має вважати його придатним. Покупець втрачає знижку в останній день дії коду.
Severity Normal: код працює в усі дні, окрім останнього, основна функція збережена. Priority P3: не блокує виконання інших тестів.

### Preconditions
Юніт-тест, без браузера/сесії. Клас `PromoCodeValidator`, метод `validate`.

### Steps to reproduce
1. Створити `PromoCodeValidator`.
2. Створити `new PromoCode("WINTER26", PromoCode.Type.PERCENT, new BigDecimal("10"), LocalDate.of(2026, 12, 31), false, false)`.
3. Викликати `validate(promo, LocalDate.of(2026, 12, 31), new BigDecimal("500.00"))`.

### Actual result
Після кроку 3: `valid() = false`, причина відмови непорожня (строк дії минув).

### Expected result
Після кроку 3: `valid() = true`, `reason() = ""` (BL-70: день закінчення включно).

### Environment
JDK 17 (Temurin), Maven 3.9, JUnit 5.10.2; модуль `shopline-module` v1; запуск: `mvn test -Dtest=PromoCodeValidatorRulesTest`.

### BUG-020: PromoCodeValidator приймає й застосовує використаний одноразовий промокод (BL-70, BL-80)

Мітки: `severity:major`, `priority:P3`, `status:new`, `sprint:4`, `module`

**Severity:** Major   **Priority:** P3   **Status:** New  
**Linked:** tests `PromoCodeValidatorRulesTest.singleUseCodeMustNotBeUsed` [singleUse=true, used=true], `PromoCodeValidatorRulesTest.applyRejectsUsedSingleUseCode`; requirement BL-70, BL-80

### Description
BL-70 вимагає, щоб одноразовий код був ще не використаний, а BL-80 — щоб `apply` перевіряв придатність за BL-70, зокрема ознаку використання одноразового коду. Метод `validate` ознаку `used` ігнорує: використаний одноразовий код вважається придатним, і `apply` повертає суму знижки замість `IllegalArgumentException`. Уточнення BL-80 про джерело ознаки використання — пропозиція, не підтверджена замовником; сам виняток для використаного одноразового коду вимагає BL-70.
Severity Major: порушено правило обмеження знижки, одноразовий код можна застосовувати повторно, важлива функція працює не повністю. Priority P3: не блокує виконання інших тестів.

### Preconditions
Юніт-тест, без браузера/сесії. Клас `PromoCodeValidator`, методи `validate` і `apply`.

### Steps to reproduce
1. Створити `PromoCodeValidator`.
2. Створити `new PromoCode("WINTER26", PromoCode.Type.PERCENT, new BigDecimal("10"), LocalDate.of(2026, 12, 31), true, true)`.
3. Викликати `validate(promo, LocalDate.of(2026, 12, 30), new BigDecimal("500.00"))`.
4. Викликати `apply(promo, LocalDate.of(2026, 12, 30), new BigDecimal("500.00"))`.

### Actual result
Після кроку 3: `valid() = true`, `reason() = ""`.
Після кроку 4: виняток не кинуто, повернено `50.00`.

### Expected result
Після кроку 3: `valid() = false`, причина відмови непорожня (BL-70).
Після кроку 4: `IllegalArgumentException` із причиною відмови (BL-80).

### Environment
JDK 17 (Temurin), Maven 3.9, JUnit 5.10.2; модуль `shopline-module` v1; запуск: `mvn test -Dtest=PromoCodeValidatorRulesTest`.
