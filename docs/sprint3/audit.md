## 2. Перевірка інкременту на DoD

| Критерій DoD | Норматив | Фактично | Виконано |
|---|---|---|---|
| Тест-кейси | ≥ 25 | 31 | так |
| Шість обов'язкових полів у кожному кейсі | 100 % | 31/31 | так |
| Кожен кейс простежується до вимоги SRS-1.1 | 100 % | 31/31 | так |
| F- та GUI-вимоги покриті або внесені до непокритих із причиною | 100 % | покрито 23; F-130 — частково з причиною; GUI-80, GUI-100 — з причиною | так |
| Усі кейси виконані; статус, дата, виконавець, середовище | 100 % | 31/31 (passed 19, failed 12, blocked 0) | так |
| Для failed — Bug ID, для blocked — причина | 100 % | 12/12 failed мають Bug ID | так |
| Звіти про дефекти | ≥ 10 | 14 | так |
| Рівні severity | ≥ 3 | 4 (Major 3, Normal 5, Minor 5, Trivial 1) | так |
| Кожен звіт містить усі поля шаблону 4.11 | 100 % | немає поля Status; BUG-011, BUG-012 без вкладень | ні |
| Позначка рецензента з датою на кожному кейсі | 100 % | 31/31 (аркуш Review) | так |
| Позначка рецензента з датою на кожному звіті | 100 % | у `bug-reports/*.md` — «очікує рецензії» | ні |
| Трекер налаштовано, посилання в README | так | шаблон issue і мітки є; у README посилання лише на репозиторій | частково |
| Таблиця розподілу задач | так | `task-board.md` | так |
| Протокол ретро | так | після демо | — |

**Що виправити до демо:**
1. Внести позначку Reviewer із датою в кожен звіт `bug-reports/BUG-NNN.md` (Кочаров Д.).
2. Додати поле Status у звіти; додати знімки до BUG-011 і BUG-012 (Бойко Є.).
3. Додати в README посилання на issues з міткою `sprint:3` (Матвієнко В.).
