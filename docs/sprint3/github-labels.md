# Мітки GitHub Issues для звітів про дефекти (спринт 3)

Завдання 2.2 (Інженер з тестування). Набір міток відповідає розділам 4.12–4.14 методички:
`severity:*` — серйозність, `priority:*` — пріоритет, `status:*` — стан життєвого циклу, `sprint:3` — приналежність до спринта.
Стани «Open/Closed» у GitHub задає сам issue; проміжні стани позначаються мітками `status:*`.

| Мітка | Колір | Опис |
| --- | --- | --- |

| `severity:critical` | `#D93F0B` | Відмова системи, втрата даних, блокування ключової функціональності |

## Створення міток одним скриптом

Потрібні встановлений [GitHub CLI](https://cli.github.com/) і вхід (`gh auth login`) під обліковим записом із правом запису в репозиторій.
Команди ідемпотентні завдяки `--force`: наявна мітка оновлюється, а не дублюється.

```bash
REPO=ybelinska0/TZYAPZ_TeamB

mk() { gh label create "$1" --color "$2" --description "$3" --repo "$REPO" --force; }

mk "severity:blocker"  B60205 "Блокує тестування"
mk "severity:critical" D93F0B "Відмова системи, втрата даних, блокування ключової функціональності"
mk "severity:major"    E99695 "Серйозна втрата функціональності"
mk "severity:normal"   FBCA04 "Користуватися можна, але є незручності"
mk "severity:minor"    C2E0C6 "Незначна втрата функціональності; проблема інтерфейсу"
mk "severity:trivial"  EDEDED "Косметичні дефекти"

mk "priority:P1" B60205 "Блокує будь-яке подальше виконання кейсів"
mk "priority:P2" D93F0B "Блокує виконання поточного або кількох кейсів"
mk "priority:P3" 0E8A16 "Усе інше: кейси виконуються далі"

mk "status:new"      1D76DB "Звіт створено"
mk "status:open"     0052CC "Підтверджено, призначено виконавця"
mk "status:rejected" CFD3D7 "Не дефект або дублікат"
mk "status:deferred" BFD4F2 "Відкладено"
mk "status:fixed"    5319E7 "Виправлено, чекає перевірки"
mk "status:verified" 0E8A16 "Перевірено в новій збірці"
mk "status:reopened" E4E669 "Повторна перевірка — failed"

mk "sprint:3" 006B75 "Інкремент спринта 3"
```

Без GitHub CLI: Issues → Labels → New label — по одній мітці за таблицею вище.
