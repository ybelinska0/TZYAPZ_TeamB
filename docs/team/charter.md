* **Основний канал зв'язку:** Telegram-чат.
* **Мова комунікації та документації:** професійна українська.
* **Синхронізація:** регулярні зустрічі для обговорення статусу завдань (Daily/Weekly Standup) відбуваються [щосереди].

## 4. Правила роботи з репозиторієм (Git Flow)
* **Основна гілка:** `main` — завжди містить стабільну, перевірену версію документації та схем.
* **Робочі гілки:** створюються від `main` для кожного нового об'ємного завдання (наприклад, `feature/bpmn-models`).
* **Злиття (Merge):** здійснюється через Pull Request (PR) після перевірки (Review) мінімум одним учасником команди. Якщо завдання виконується індивідуально в межах зони відповідальності, допускається прямий push у `main` за умови відсутності конфліктів.
* **Коміти:** повідомлення комітів мають бути чіткими та відповідати на питання «Що зроблено?» (наприклад: `Додано статут команди charter.md`).

## 5. Definition of Done (Критерії готовності)
Завдання вважається виконаним, якщо:
1. Усі необхідні файли створені та відформатовані в Markdown (або експортовані в PDF/PNG для візуальних схем).
2. Файли розміщені у правильній директорії згідно зі структурою інкременту (наприклад, `docs/sprint1/`).
3. Вимоги методичних вказівок повністю дотримані.
4. Файли успішно завантажені у віддалений репозиторій на GitHub без конфліктів злиття.
